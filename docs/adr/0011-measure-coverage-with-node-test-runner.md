# 0011. コードカバレッジは node:test 組み込みの機能で取得し、100% を求める

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

TDD で書いたコードは、本来すべての行と分岐がテストから実行されているはずである。それを仕組みで確かめ、テストのないコードが紛れ込んだら気づけるようにしたい。

候補は c8 や nyc などの外部ツールと、Node のテストランナー組み込みのカバレッジ機能(`--experimental-test-coverage`)である。組み込みの機能は type stripping で実行した `.ts` ファイルもそのまま集計でき、追加の依存がいらない。

## 決定

- `node --test` 組み込みのカバレッジ機能を使い、`npm run test:coverage` で実行する。
- 集計の対象は `src/**/*.ts` とし、テストコード(`src/__tests__/**`)は除く。
- `--test-coverage-include-all` を付け、テストから一度も読み込まれないソースファイルも集計に含める。
- 行・分岐・関数のカバレッジがいずれか 100% を下回ったら失敗させる。
- `npm run check` は `npm test` の代わりに `npm run test:coverage` を実行する。

## 結果

- テストのないファイルや分岐を追加すると、`npm run check` と CI が失敗する。
- 組み込みのカバレッジ機能はまだ実験的機能なので、Node の更新で挙動やフラグが変わる可能性がある。
- テストから読み込まれないファイルは、行カバレッジは 0% と表示されるが、関数カバレッジは 100% と表示される。行の閾値で検出できるので実害はない。
- カバレッジ 100% は「すべての行が実行された」ことしか保証しない。テストが振る舞いを十分に確かめているかは mutation testing(ADR 0012)で補う。
