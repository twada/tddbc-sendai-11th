# 0016. Property-based Testing を fast-check で行い、例によるテストを補う

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

これまでのテストは、お題の例やペアで決めたことを、具体的な入力と期待値で書いた「例によるテスト」だった。例によるテストは仕様の説明として読みやすい反面、試せる入力は書いた分だけである。

このプロジェクトの入力の空間は小さく、構造がはっきりしている。スキットルは 12 本で、1 回の投てきは「12 本の中から重複なく選んだ部分集合」である。また、次のように、どの入力でも成り立つべき性質がある。

- 倒した順序を入れ替えても点数は同じ
- 得点の推移は減らない
- 投てきが増えても、それまでの推移は変わらない

こうした性質は、ランダムに生成した多数の入力で確かめる Property-based Testing(PBT)に向いている。

JavaScript / TypeScript の PBT ライブラリとしては fast-check が標準的である。導入にあたって、次のことを確かめた。

- `fc.assert` を node:test の `it` の中で呼ぶだけで動く。テストランナー向けの追加パッケージは要らない。
- 性質の中で `assert` が失敗すると、fast-check の反例(Counterexample)と再現用の seed / path に加えて、`cause` として power-assert の図が表示される。
- StrykerJS の tap-runner でもそのまま動く。

## 決定

- fast-check を使う。導入時点の最新版 4.10.2 は公開から 1 か月以上経っていたので、そのまま採用する。
- 例によるテストは残す。お題の例やペアで決めたことの記録として読めるようにし、PBT はそれを置き換えずに、普遍的な性質を補う。
- 性質のテストは `*.property.test.ts` という別ファイルに置く(`points.property.test.ts`、`score.property.test.ts`)。入力の生成器(arbitrary)は `src/__tests__/arbitraries.ts` にまとめる。
- 1 回の投てきは `fc.shuffledSubarray` で「重複なく選び、順序もばらばらにした」スキットルとして生成する。重複を含む投てきは、正しい投てきに、その中の 1 本と同じ番号を任意の位置に差し込んで作る。
- 乱数の seed は固定せず、実行のたびに違う入力を試す。失敗したときは、fast-check が表示する seed と path で再現する。
- 確かめる性質は次のとおり。
  - `pointsOf`: 1 本なら番号、2 本以上なら本数が点数。点数は 0〜12。倒した順序によらない。重複が混ざると、位置にかかわらずその番号を含む `Error` になる。
  - `scoreHistoryOf`: 長さは投てきの回数と同じ。得点は減らない。隣り合う得点の差はその投てきの点数。最後の値は現在の得点。
  - `scoreOf`: 前半と後半の得点の和は全体の得点と同じ。投てきが増えても、それまでの推移は変わらない。投てきの順序を入れ替えても、現在の得点は変わらない。
- `skittle` の表明(ADR 0015)はテストしない方針なので、範囲外の番号は生成しない。

## 結果

- 性質のテストだけで Stryker を実行しても、36 個の変異体をすべて検出した(3 回実行して 3 回とも 100%)。性質が実装の誤りを捉えられることを確かめられた。
- テストは 28 件から 40 件になった。実行時間は 0.2 秒ほどで、mutation testing も 3 秒ほどで終わる。
- seed を固定していないので、まれにしか現れない反例で、ある回だけ失敗することがありうる。それは見逃していたバグなので、表示された seed で再現し、例によるテストとして残してから直す。
- 今後、ある変異体を性質のテストだけが検出するようになると、mutation score が実行ごとに揺れる可能性がある。CI が不安定になったら、Stryker の実行時だけ seed を固定するなどの対策を検討する。
- `shuffledSubarray` で生成した反例は縮小(shrink)があまり進まず、最小の反例にならないことがある。
