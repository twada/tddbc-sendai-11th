# 0010. 得点は投てきの履歴全体から毎回計算する

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

STEP 02 で「得点(score)」が導入された。得点は 0 点から始まり、複数回の投てきの点数を合計したものが現在の得点になる。

得点の求め方には、次の選択肢があった。

- **点数を合計する**: `scoreOf(pointsOf(…), pointsOf(…))`。得点は点数だけに依存する。ただし `Points` は `number` の別名なので、任意の数値も渡せてしまう。
- **投てきから計算する**: `scoreOf([…], […])`。お題の「投てきを繰り返して得点を積み重ねる」という言葉に沿う。

また「現在の得点」の求め方として、履歴全体から毎回合計する方法と、前の得点に 1 回分の点数を足して更新していく方法があった。

STEP 01-2 では、投てきを記録したり並べたりする仕様が出てきたら、投てきを独立した型にすることにしていた。

## 決定

- 投てきを型 `Throw = readonly Skittle[]`(1 回の投てきで倒したスキットル)として表す。いまの仕様で投てきが持つ情報は倒したスキットルだけなので、オブジェクトでは包まず、配列の別名とする。
- 得点は型 `Score = number` の別名とする。点数を足したものなので、点数と型では区別しない。
- 得点は `scoreOf(...throws: readonly Throw[]): Score` で、投てきの履歴全体から毎回計算する。各投てきの点数は `pointsOf` で求めて合計する。投てきが 0 回なら 0 点。
- お題に書かれていないことは次のように扱い、テストとして残す。
  - 投てきどうしは独立して扱い、異なる投てきで同じ番号のスキットルを倒しても重複とみなさない。
  - 1 回の投てきの中に重複があれば、`pointsOf` が投げる `Error` をそのまま伝える。途中までの得点は返さない。
  - 得点に上限は設けない。

## 結果

- `scoreOf` は純粋関数 1 つで済み、投てきの点数のルールは `pointsOf` に集まったままになる。
- 投てき 0 回(`scoreOf()`)と、1 回投げて 1 本も倒さなかった投てき(`scoreOf([])`)を区別して表せる。
- 呼び出すたびに履歴全体を計算し直す。得点の状態によってルールが変わる仕様が出てきたら、得点を更新していく方法への変更を検討する。
