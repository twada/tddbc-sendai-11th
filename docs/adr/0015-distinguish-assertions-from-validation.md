# 0015. 検証と表明を区別し、型で保証した前提は表明で実行時にも確かめる

- ステータス: 承認済み
- 日付: 2026-10-24
- [ADR 0009](0009-validate-statically-where-possible-otherwise-at-runtime.md) を補足する

## コンテキスト

ADR 0009 では「入力は可能な限り静的に検証し、できなければ実行時に検証する」と決め、スキットル番号の範囲(1〜12 の整数)は型 `SkittleNumber` で保証して、実行時には検証しないことにした。

しかし型が守ってくれるのは、TypeScript から型検査を通して呼ばれる場合だけである。`as` による型の偽装、JavaScript からの呼び出し、外部データの取り込みなどでは、範囲外の値が素通りして、もっともらしい Skittle が作られてしまう。型で担保した前提が実行時に無防備なのは避けたい。

一方で、型で担保した制約を「実行時に検証してテストする仕様」に格上げすると、型を偽らないとテストが書けず、ADR 0009 の方針とも食い違う。

## 決定

- 「検証(validation)」と「表明(assertion)」を区別する。

|              | 検証                                         | 表明                                             |
| ------------ | -------------------------------------------- | ------------------------------------------------ |
| 何を守るか   | 呼び出し側の誤り(例: 1 回の投てきの中の重複) | プログラムのバグ(型で保証した前提が破られた)     |
| 失敗したとき | `Error` を投げる                             | `node:assert` の `AssertionError` を投げる       |
| テスト       | 仕様としてテストする                         | 正しいプログラムでは失敗しないので、テストしない |
| 対象         | 静的に検証できない制約(ADR 0009)             | 静的に検証できる制約の、実行時の再確認           |

- `skittle` 関数に、スキットル番号が 1〜12 の整数であることの表明を 1 本加える。条件は `Number.isInteger(number) && 1 <= number && number <= 12` とし、メッセージには受け取った値を含める(例: 「スキットル番号は 1〜12 の整数: 13」)。`Number.isInteger` は `NaN`、`Infinity`、数値以外の値にも `false` を返すので、この 2 種類の条件で `SkittleNumber` の条件をすべて表せる。
- 表明は `if (...) throw` ではなく `assert(...)` で書く。分岐を増やさないので、ブランチカバレッジ 100%(ADR 0011)を保てる。
- 表明はテストしないため、mutation testing(ADR 0012)では表明の条件やメッセージを変異させた変異体が生き残る。表明の文を `// Stryker disable all: 理由` と `// Stryker restore all` で囲み、変異の対象から外す。

## 結果

- `as` で型を偽ったり JavaScript から呼んだりして範囲外の番号を渡すと、`skittle` が `AssertionError` を投げる。`0`、`13`、`1.5`、`NaN`、`Infinity`、文字列の `"5"` で確認した。
- 表明を加える前は、型レベルテストが実行時にも `skittle(0)` などを呼んでいた。表明によってこれらが失敗するようになったため、型レベルテストの呼び出しを `void (() => { ... })` で包み、実行しない形にそろえた。
- 表明を加えた直後、表明を変異させた 7 個の変異体が生き残り、mutation score は 85.42% だった。変異の対象から外して 100% に戻した。
- 表明が守るのは `skittle` 関数を通った値だけである。TypeScript の型は構造で一致を判定するので、`{ number: 13 }` のようなオブジェクトリテラルを Skittle として渡す経路は、引き続き防げない。
- 文字列の `"5"` を渡したときのメッセージは「スキットル番号は 1〜12 の整数: 5」となり、数値の 5 と見分けにくい。必要になったら、メッセージで値の型も分かるようにする。
