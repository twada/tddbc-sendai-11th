# 0008. スキットル番号の範囲は型で保証し、実行時には検証しない

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

スキットル番号は 1〜12 の 12 種類しかない。お題では、範囲外の入力(0、13、1.5 など)の扱いはペアで決め、その決定をテストとして残すことになっている。

現時点ではユーザー入力や外部データを受け取る境界がなく、ドメインの関数を呼ぶのはテストコードだけである。

## 決定

- `SkittleNumber` を `1 | 2 | … | 12` のリテラルユニオン型とし、範囲外の番号はコンパイル時の型エラーとして防ぐ。
- 実行時の範囲検証(例外を投げる、Result 型で返すなど)は行わない。
- この決定は `src/__tests__/skittle.test.ts` に `// @ts-expect-error` を付けたテストとして残し、`npm run typecheck` で検証する。範囲外の番号が型エラーにならなくなると、`@ts-expect-error` が不要になり `tsc` が失敗する。

## 結果

- 実行時の検証コードとエラー表現を設計せずに済み、ドメインのコードが小さく保てる。
- 型レベルのテストは `npm test` では検証されない。`npm test` の段階では、範囲外の番号を渡してもオブジェクトが作られるだけで成功する。型レベルの決定を検証するには `npm run typecheck`(または `npm run check`)が必要。
- 外部からの入力(`number` 型の値)を受け取る仕様が出てきたら、入力の境界で検証してエラーを表現する方法を、新しい ADR で決める。
