# 0014. 得点の推移は、各投てきが終了した時点の得点の配列で表す

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

STEP 03 で、現在の得点だけでなく、各投てきが終了した時点の得点(その時点の得点)も確認できるようにすることになった。お題の例は「1回目に5本、2回目に11番を1本、3回目は0本、4回目に3本倒したとき、各投てきが終了した時点の得点は 5, 16, 16, 19」である。

結果を配列で返すことは決まっていたが、その中身として次の 2 案があった。

1. 各投てきが終了した時点の得点(累積値)`[5, 16, 16, 19]`
2. 各投てきの点数 `[5, 11, 0, 3]`

両案について賛成・反対の論点を出し、根拠の強さで比べた。

| 根拠の種類                                         | 強さ                                       | 案 1                                | 案 2                       |
| -------------------------------------------------- | ------------------------------------------ | ----------------------------------- | -------------------------- |
| お題の文面と例                                     | 強い                                       | 例の値と一致する                    | 例と食い違う               |
| お題が定義した用語(点数 / 得点)                    | 強い                                       | 「その時点の得点」と一致する        | 点数の列になる             |
| 設計の原則(関心の分離、組み立てやすさ、重複の排除) | 中くらい                                   | 累積のルールを 1 か所にまとめられる | 部品が小さく関心が分かれる |
| 将来の仕様の予想                                   | 弱い(お題は予想による作り込みを禁じている) | —                                   | 点数の情報を保存できる     |

案 1 は強い根拠に支えられ、案 2 の長所は中くらい以下の根拠に依存していた。また、案 2 はそれだけでは要求(その時点の得点)を満たさない。

## 決定

- 得点の推移は `scoreHistoryOf(...throws: readonly Throw[]): readonly Score[]` で求める。i 番目(0 始まり)の要素が、i+1 回目の投てきが終了した時点の得点である(案 1)。
- 投てきが 0 回なら空の配列を返す。「各投てきが終了した時点の得点」なので、投てきがなければ記録もない。
- 案 2 の「各投てきの点数の列」は公開せず、`scoreHistoryOf` の内部で使う。点数の列を作ってから先頭から足し上げることで、「投てきの評価」と「積み重ね」を分ける。
- 点数を積み上げるルールは `scoreHistoryOf` だけに置き、`scoreOf` は「推移の最後の値(投てきがなければ 0 点)」として求める。
- 途中の投てきに重複があれば、`scoreOf` と同じく `Error` を投げ、途中までの推移は返さない。
- 戻り値は `readonly` の配列とし、呼び出し側が書き換えられないようにする。

## 結果

- お題の例をそのままテストの期待値にでき、`scoreOf` と `scoreHistoryOf` の累積のルールが食い違うことがなくなった。
- `scoreOf` は呼び出すたびに推移全体を作る。投てきの数が少ないうちは問題にならない。
- 得点表に各投てきの点数も表示する仕様や、得点の積み重ね方が足し算でなくなる仕様が出てきたら、点数の列を公開するかどうかを改めて検討する。
