# 0001. アーキテクチャ上の決定を ADR として記録する

- ステータス: 承認済み
- 日付: 2026-10-24

## コンテキスト

このリポジトリは TDD 学習のための演習プロジェクトであり、ツール選定や設計判断の「なぜ」を後から振り返れることに学習上の価値がある。コードやコミット履歴だけでは、検討した代替案や判断の前提が残らない。

## 決定

- 重要な決定は `docs/adr/NNNN-<kebab-case-title>.md` に 1 決定 1 ファイルで記録する。
- 形式は Michael Nygard 方式(コンテキスト / 決定 / 結果)を基本とし、日本語で書く。
- 一度承認した ADR は書き換えず、方針を変えるときは新しい ADR を追加し、旧 ADR のステータスを「〜により置き換え」とする。
- 「いま現在どうなっているか」は `docs/architecture.md` にまとめ、ADR は「なぜそうなったか」の履歴とする。

## 結果

- 演習の途中で方針を変えた場合も、変更前後の判断理由をたどれる。
- 決定ごとに小さなドキュメントを書く手間が発生する。
